# UoBTKD Training Suite

An English web-interface build is in `LedaSport-English`. The original `LedaSportXunLian_V202` folder is untouched.

Close the original application, then open `LedaSport-English/Start-English.cmd`. Both copies use the same local server ports, so run one at a time. The launcher preserves the vendor executable and hardware library. The translated interface is under `nginx/html/train`.

This build uses the supplied native receiver shell with a customised English interface. The generated executable has translated title text and no elevation requirement. Existing athlete/team names remain editable user data. Hardware operation still requires checking on the PSS computer; automated checks use simulated receiver messages.

Round start, pause, resume, round end, and break end use locally synthesised tones. Valid scored hits use the supplied `hit.mp3`, with pitch variations for each court/person and a preview button. Sound on/off and volume are saved using the top-right controls. Free Training uses start/pause/resume cues without a round timer.

The desktop shell plays generated WAV files through its native `HostPlaySound` callback; browser previews use Web Audio with a PCM fallback. Native volume uses ten steps. The native bank supplies 16 court cues and 256 individual cues (individual IDs beyond 256 reuse the bank).

`src/audio/hit.mp3` is the source clip; `src/audio/hit.wav` is its PCM conversion for native playback. If replacing the MP3 later, regenerate the WAV as mono 16 kHz PCM16 before rebuilding. Browser hit previews play the MP3 directly.


To reproduce the package, run `python tools/build_english.py`. Rebuilding updates interface assets and preserves the working copy’s runtime data. Run `node tools/verify_scoring.cjs` to check JavaScript syntax and the original and translated scoring handlers.

The build translates 26 JavaScript bundles and the HTML title/language. Spreadsheet encoding tables and legacy sex markers in the weight-category parser are preserved. Receiver communication is preserved. Court assignments now control blue/red hit routing; point values and thresholds remain unchanged.

See `PSS-LOGIC.md` for the rules when several protectors share one receiver.

Choose Court 1–16 beside each athlete. Each court accepts at most two; the first in roster order is Blue and the second Red. Train opens those courts; Start begins the timer. Court and colour checks: `node tools/verify_controller.cjs`.


Sensor levels: on the training screen open Sensor levels (top left). The panel shows up to 40 received impacts, device ID, court/side, raw value, raw/40 level, and the threshold/result at receipt. It monitors while scoring is paused or stopped as well as while running. Listen for hits sends the existing StartWork command to all four protector types without starting the timer; closing the panel stops a listening session it owns unless training has taken over. A receiver connection is required.

Body thresholds can now be entered directly from 0 to 71 levels (raw 0–2840), and +/- supports the same range. This is a software limit, not a verified hardware range. The original raw = level * 40 conversion is preserved. Court thresholds persist through Train preparation. Helmet threshold entry is available in the sensor panel too.

Pressure-only/no-socks: no documented RFID/NFC bypass command was found in the supplied app. The support-check button explains this; it does not enable a device mode. The scoring code already accepts received impact values without a sock check. Compare gentle impacts with and without socks in Listen for hits. No sockless messages could indicate filtering upstream, but does not isolate firmware from receiver, connectivity, or sensor behaviour. Identifying an actual bypass requires protocol/firmware support or controlled captures from a known pressure-only mode. No guessed WriteParams or gate/level changes were sent.

Validation: node tools/verify_sensors.cjs checks monitoring while stopped, parsing, higher thresholds, persistence, panel lifecycle, and the exact start/stop commands. No physical sensors were exercised.

Source layout: `src/runtime` contains protocol, court, sensor and presentation modules; `src/styles` holds the theme; `src/integration` contains vendor-view render expressions. `src/translations.json` is the translation source. `tools/build_english.py` integrates these with the original package. Run `pnpm test` for logic/build checks and `pnpm test:ui` for isolated browser checks (requires Playwright and Microsoft Edge).


Local barebones update: the interface is text-only, with no branding or image requests. Equipment status is shown as text. Builds stage a native shell update that removes the administrator requirement, translates known native labels, and replaces the vendor icon with the supplied UOB Taekwondo icon. Close the existing app before running Start-English.cmd; the launcher installs the staged copy. The original vendor executable is preserved in the original package. The custom splash screen is installed from src/assets/splash.png; licence notices are retained separately in notices/Vendor-Licence.txt. Windows security settings and licence/account checks are unchanged. Physical hardware operation still needs user review. This update has not been pushed.

App name: UoBTKD Training Suite. The centred opening page uses Start to open athlete setup. The launcher applies the same desktop window title without requesting administrator rights. This remains a local review build.

The full desktop title is now stored directly in the prepared executable. The temporary PowerShell title helper has been removed. Both Alt keys are removed from the native play/pause callback; Space remains available. See KEYBOARD-SHORTCUTS.md for verified bindings. Changes remain local for review.


Free Training is available from the centred start page alongside Court Training. It has no scoring clock, rounds, pairings, or court capacity. Each matched equipment message above that person's threshold adds one hit received, regardless of body/helmet type. Scores measure hits on the wearer, not points earned by an unidentified attacker. People are added manually and named inline; renaming/removal and individual/group resets stay isolated from court data. The group total sums the currently listed people, so removing a person removes their score from the total.

Names, assignments, thresholds, and counters are stored in the separate bristol_free_training_v1 local-storage record. Reopening always pauses collection. A background 30-second transport renewal reuses the existing StartWork,time:60,gate:1,level:1 command so device work can continue without a visible session deadline; it does not call the court timer or alter court timing settings. Pause and navigation away stop the work session and clear the renewal. Physical long-session behaviour requires testing with the receiver. No new RFID command or bypass is involved. Tests: node tools/verify_free_training.cjs; browser checks also cover adding, renaming, removing, resets, reload persistence, and mode isolation. Nothing has been pushed.

App artwork: src/assets/app.png is the source logo, src/assets/app.ico is the Windows icon, and src/assets/splash.png is the 1600 × 1040 startup image. The build retains the high-resolution source, exports a smoothly filtered RGB splash at the native 540 × 351 display size to LedaSport-English/res/splash.png, and embeds the ICO in the executable. Install requirements-build.txt before building.

Equipment management: the Equipment button is available alongside sound controls on every page. Set each saved device's colour and size directly in the inventory table; its raw ID stays in that detail view. The same registry supplies athlete, Free Training, court, and Competition labels. Unnamed devices have numbered placeholders until configured. Duplicate colour/size labels remain stable while any devices are connected. An empty receiver device list clears suffix allocations, so the next connection cycle starts without a suffix, then (2), (3), etc.; colour, size, type, and device IDs are preserved. A network disconnect alone is not treated as proof of an empty device list. The registry persists as uobtkd_equipment_v1; live battery values start unknown each session. DevBattery batt_id values 0–3 mean Empty/Low/Medium/High, not exact percentages. Explicit percentage/percent/battery_percent/battery_percentage fields are displayed when valid. Refresh sends only existing device-list and battery queries.

Competition: Competition opens with protector testing before Enter match mode. Its separate best-of series uses the configured round count, with per-round score/penalty resets and a recorded winner, score and method. Settings exposes maximum gam-jeoms (default 5) and point gap (default 15; 0 disables it). PTG/PUN/time-expiry PTF are automatic; ties wait for a referee SUP decision. KO/RSC/DSQ/WDR/DQB are manual whole-match decisions. Undo last round restores a result for correction while preserving current equipment. Reset match clears the series and adopts saved rules. Equipment navigation preserves the series and clock, returning paused. See PSS-LOGIC.md for decision semantics and the rules reference.

Navigation update: Court Training on the main menu prepares saved court assignments and opens GameCtrl directly, including an empty layout when no athletes are assigned yet. Equipment now opens a physical-device inventory only. Type, colour, and size are edited independently in the table, with automatic saving on field change. Battery status, refresh, manual addition, search, and expandable IDs are on the same page. Athlete records are not listed there. Escape closes the active dialog first, otherwise uses in-app route history to return to the previous screen. The native fullscreen Escape branch is replaced with the existing proven JavaScript callback mechanism, calling OnVkEscape; held-key repeats are consumed. Space and Alt handling are preserved. Leaving a live mode stops tracking; returning from Equipment preserves court scores and restores Competition as one court in a stopped state.

The Equipment table now has an ID dropdown column instead of Information. Show ID expands the immutable hardware ID inline.

Equipment bindings: discovery now maintains a catalog of available hardware separately from saved equipment entries. The original vendor rule infers Blue from final characters 1/3/5/7/9/A/C/E and Red from 0/2/4/6/8/B/D/F. Type comes from DevState: huju/xlhuju are body, toukui/xltoukui are head. Existing user-set colours are retained; blank/new entries use the inferred colour. ID choices exclude IDs claimed by other entries and filter by detected category and inferred colour. Selecting a replacement keeps the entry's size/name numbering and updates saved court, free-training, competition-setup and suspended-competition device references. Deleting removes the entry and clears those references, while leaving the device available to claim again; discovery does not recreate deleted entries. New entries can select discovered unclaimed IDs, with a manual offline-ID fallback. Colour is a Red/Blue dropdown; size remains manual. Offline cached IDs are labelled offline in the dropdown.

Duplicate-label correction: displayed suffixes are computed only from current, non-deleted saved table entries in stable table order. Historical counters, unclaimed hardware, and previously used names do not count. A single Blue 3 is always Blue 3, even if its saved legacy ordinal is 3. Removing or renaming a matching row immediately updates the remaining labels. Radio connectivity does not remove saved rows from this comparison.


Roster-free participants: Court Training reads saved per-court names and guard assignments only; it no longer resolves guards from athlete storage. Competition setup stores two directly editable names and equipment choices. Free Training has no existing-athlete import or roster lookup. Names are independent of device IDs. Choosing a guard already assigned within the active mode atomically exchanges the two same-type assignments; choosing an unused guard replaces only that participant's assignment. Scores, hit counts, thresholds, names, round state, and timer state do not move with a guard. Stale live-impact displays are cleared on reassignment; subsequent messages use the new ownership immediately. Court layout changes keep the same live slots rather than reloading assignments. The old vendor athlete database is left untouched but is no longer used by these modes.
